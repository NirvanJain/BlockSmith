# Fix Database Layer — Align Rust Code with New Migration

## Problem

The migration was rewritten from 3 tables (users, contributions, blocks) with `i64` IDs to 25+ tables with UUID primary keys. But the Rust code still references the old schema:
- `database/blocks.rs`, `contributions.rs`, `analytics.rs`, `schema.rs`, `queries.rs`, `seed.rs` — all query non-existent tables
- All 22 model structs use `i64` IDs, none derive `sqlx::FromRow`
- Route handlers (`routes.rs`, 556 lines) write all SQL inline — the database module is unused
- 13 of 22 models are dead code

## Approach

Rewrite the `database/` module to be the single data-access layer, create proper `FromRow` models, and refactor route handlers to call db functions instead of inline SQL.

## Phase 3: Refactor Route Handlers

**File: `src/routes.rs`** — Replace all inline SQL with calls to `crate::database::*` functions.

Each handler becomes:
1. Extract state (`State(pool)`)
2. Call a db function
3. Map result to response struct
4. Return JSON

Example transformation:
```rust
// BEFORE (inline SQL):
let row = sqlx::query("SELECT id FROM users WHERE clerk_user_id = $1")
    .bind(&clerk_user_id)
    .fetch_optional(pool).await?;

// AFTER (db function):
let user = crate::database::users::find_user_by_clerk_id(pool, &clerk_user_id).await;
```

**Also update:**
- `src/auth/clerk_webhooks.rs` — use db::users and db::profiles functions
- `src/github/webhooks.rs` — use db::users and db::activities functions
- `src/realtime/websockets.rs` — use db::users::find_user_by_clerk_id
