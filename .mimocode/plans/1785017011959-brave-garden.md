# Migration Plan: MongoDB → Cloudflare D1

## Context

BlockSmith is a Rust/axum backend with MongoDB, React/TypeScript frontend. The project **originally had a PostgreSQL schema** (see `backend/migrations/20260603000000_openhub_schema.sql` — 330 lines, 25+ tables). It was later migrated to MongoDB but the SQL schema was kept. We're now moving to **Cloudflare D1** (SQLite on Cloudflare's edge).

D1 only works inside **Cloudflare Workers** (JS/WASM runtime), so the Rust/axum backend must be rewritten in TypeScript. The existing SQL migration schema is a strong starting point — it's actually more complete than the MongoDB implementation.

## Architecture

```
Cloudflare Workers (TypeScript)
├── Hono (HTTP framework, lightweight, built for Workers)
├── Drizzle ORM (type-safe SQL, D1 adapter)
├── D1 (SQLite database)
├── Cloudflare KV (replaces Redis for caching)
└── Durable Objects (replaces WebSockets/tokio channels)

Frontend: stays as-is (React + Vite + Tailwind)
```

## Implementation Steps

### Phase 1: Project Setup
1. Create `backend/` directory with Cloudflare Workers + Hono + Drizzle
2. Add `wrangler.toml` with D1 binding configuration
3. Set up Drizzle ORM with D1 adapter
4. Create the D1 migration SQL (adapt from existing `20260603000000_openhub_schema.sql`)

**Files to create:**
- `backend/package.json`
- `backend/tsconfig.json`
- `backend/wrangler.toml`
- `backend/drizzle.config.ts`
- `backend/src/index.ts` (Workers entry point)
- `backend/src/db/schema.ts` (Drizzle schema)
- `backend/migrations/0000_initial.sql` (D1-compatible migration)

### Phase 2: Database Layer
Rewrite each MongoDB module as a Drizzle query module.

**Files to create:**
- `backend/src/db/index.ts` (D1 client setup)
- `backend/src/db/schema.ts` (all table definitions)
- `backend/src/modules/users.ts` — find_by_id, find_by_github_id, find_by_github_username, upsert_from_github, update, update_reputation, delete_by_id
- `backend/src/modules/profiles.ts` — get, upsert
- `backend/src/modules/repositories.ts` — upsert, increment_prs_merged, record_reputation_change
- `backend/src/modules/issues.ts` — get_discovery
- `backend/src/modules/badges.ts` — get_all, get_user_badges, award_badge
- `backend/src/modules/conversations.ts` — get_user_conversations, find_existing_dm, create, add_participant, get_participants
- `backend/src/modules/messages.ts` — get_messages, create
- `backend/src/modules/activities.ts` — create, get_feed, get_user_activities
- `backend/src/modules/leaderboard.ts` — get_top

**D1/SQLite adaptations from PostgreSQL schema:**
- `uuid_generate_v4()` → `lower(hex(randomblob(16)))` or generate in JS
- `JSONB` → `TEXT` (store as JSON string)
- `TEXT[]` → `TEXT` (store as JSON array string)
- `TIMESTAMP WITH TIME ZONE` → `TEXT` (ISO 8601 strings)
- `CREATE EXTENSION "uuid-ossp"` → remove (not needed)
- `ON CONFLICT` → `INSERT OR IGNORE` / Drizzle's `onConflictDoUpdate`

### Phase 3: Auth (GitHub OAuth + JWT)
Port the GitHub OAuth flow and JWT handling.

**Files to create:**
- `backend/src/auth/github.ts` — exchange_code_for_token, fetch_profile, fetch_email
- `backend/src/auth/jwt.ts` — create_jwt, verify_jwt (use `jose` library for Workers-compatible JWT)

### Phase 4: API Routes
Port all routes from `routes.rs` using Hono.

**Files to create:**
- `backend/src/routes/health.ts`
- `backend/src/routes/auth.ts` — /api/v1/auth/github, /api/v1/auth/github/callback
- `backend/src/routes/feed.ts` — GET /api/v1/feed
- `backend/src/routes/leaderboard.ts` — GET /api/v1/leaderboard
- `backend/src/routes/profile.ts` — GET /api/v1/profile/:username
- `backend/src/routes/discovery.ts` — GET /api/v1/discovery
- `backend/src/routes/chat.ts` — GET/POST /api/v1/chat/conversations, GET /api/v1/chat/conversations/:id/messages
- `backend/src/routes/me.ts` — GET /api/v1/me

### Phase 5: Middleware
- CORS configuration
- JWT authentication middleware (extract user from Bearer token)

**Files to create:**
- `backend/src/middleware/auth.ts`
- `backend/src/middleware/cors.ts`

### Phase 6: Wire Up & Test
- Connect all routes in `backend/src/index.ts`
- Update `wrangler.toml` with bindings
- Test with `wrangler dev`

5. Test each endpoint:
